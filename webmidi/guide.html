GT-3 Editor · Web MIDI

User guide

An editor for the BOSS GT-3 guitar multi-effects that runs entirely in the browser. The patch's effects appear as pedals, in the order of the patch's own effect chain. The browser talks to the GT-3 directly through a USB-MIDI interface: nothing to install, no server.

Status: tried with a real GT-3 on 1 November 2026: connecting, reading, live editing and Write work. The one thing to know: the GT-3 answers only in BULK LOAD mode (reading, Write from the editor), while edits are heard at once in normal mode (section 3). On first use, read everything and save it to a file (section 10). Not checked on the unit yet: changes on the EXP / CTL / Assign and System pages.

What is this?

A browser version of the old Qt GT-3 FxFloorBoard. It sends the same MIDI messages and reads and writes the same .syx files, but it is a single web page that runs in Chrome or Edge on any computer.

It has four pages, on the tabs below the header:

  • Effects: the patch's 12 effects as pedals, the chain order and every effect parameter;
  • EXP / CTL / Assign: what the expression pedal, the CTL pedal and the 8 assigns control;
  • Library: all 340 patches in a list; read, write, copy and save many at once;
  • System: the GT-3's own settings (tuner, output, MIDI, manual mode).

1What you need

  • Browser: Chrome or Edge on Windows, macOS, Linux or Android. Safari and iPhone/iPad won't work – they have no Web MIDI.
  • A USB-MIDI interface. A decent, opto-isolated one is best (e.g. Roland UM-ONE mkII). A DOREMiDi cable works too; after long continuous traffic it sometimes "sticks" (nothing comes in) – unplug and replug its USB then. That is why the editor rests briefly after each patch when reading.
  • On Android also a USB OTG adapter.

Wiring

Computer / phoneUSB USB-MIDI interface2 × DIN GT-3 rear panel
interface OUT→GT-3 MIDI IN
interface IN←GT-3 MIDI OUT

The two plugs go in crossed over. Some cables are labelled the other way round (with where the plug goes) – if patch changes don't work, swap them. The editor needs both directions: without the GT-3's MIDI OUT it can send but not read. Push the plugs all the way in: a loose plug in the GT-3's MIDI OUT silences the whole return path.

2Starting

The editor is index.html in the webmidi folder. Three ways to open it:

  • From a web address (HTTPS): if it is hosted somewhere, open its address. This is also how it works on a phone.
  • Straight from the file: double-click index.html. If the browser doesn't ask for MIDI access this way, use the next option.
  • From a local server: in the project folder run python -m http.server -d webmidi and open the http://localhost:… address it prints.

On Windows only one program can use a MIDI port at a time. If the Qt FloorBoard or a DAW holds the interface, close it.

3Connecting and reading

The GT-3 talks MIDI in two modes, and that shapes how the editor is used:

Normal mode (patch display)BULK LOAD mode ("waiting")
Editing (knobs, switches, types, name)heard at onceonly after EXIT
Reading (patches, system settings)no answerworks
Write from the editor–works, stored on EXIT
Patch changeworks, both ways–

Into BULK LOAD on the unit: UTILITY 4 times, then PARAMETER ▶ 10 times – the display shows "waiting". Out: EXIT. No MIDI message puts it into BULK LOAD (we tried), so it is always done on the unit. The guitar still sounds in BULK LOAD.

Connecting (the Offline / port label, top right)

  1. Click Offline in the top right corner.
  2. The first time, the browser asks for permission to use MIDI devices (and SysEx): allow it. If you blocked it by mistake, turn it back on in the site settings (the icon left of the address bar).
  3. The dialog preselects the last (or the first real) MIDI port. Check Output (to GT-3) and Input (from GT-3), the Device ID (as set on the GT-3, 1 by default) and the Patch change channel (1 by default), then Connect.
  4. Connecting sends nothing to the GT-3 and needs no BULK LOAD. The label turns green. Go offline disconnects.

The editor never connects by itself on start; it only remembers the ports. Once connected it follows the unit: pick a patch on the GT-3 and the editor goes there too (the GT-3 sends a program change for every patch picked). With the connection dialog open, picking a patch on the unit shows where the GT-3 is. Changing patch with the editor's ◀ ▶ or the patch map takes the GT-3 along.

Reading (the Read (BULK) button)

Until a patch is read, the editor shows the default patch in its place – edits are still heard, but the screen doesn't show the real settings. The not read label and the gold-framed Read (BULK) button say so.

  1. On the unit, pick the patch you want to edit (the editor goes there).
  2. Put the GT-3 in BULK LOAD ("waiting") and click Read (BULK).
  3. Choose what to read: This patch (the default, about 1 second – what the GT-3 plays now and what its slot holds) or All 140 user patches (about 3 minutes). System settings too can be ticked. Then Read.
  4. At the end the editor reminds you: press EXIT on the unit. After EXIT, back on the patch display, every edit is heard at once again. Until you press I pressed EXIT, a red Press EXIT on the GT-3 stays in the header.

If reading fails: is the GT-3 really on "waiting"? Does the Device ID match the one set on the unit? Are the MIDI plugs in properly? If the interface stuck, unplug and replug its USB.

5Effects page

Patches (the patch map)

User and Preset view, 8 banks per page, paged with ‹ ›. Patches not read yet show an empty, dimmed slot with only their number; Read (BULK) reads them. A dashed yellow border marks a patch changed only in the editor (e.g. loaded from a file or written offline) – the GT-3 still holds the old one.

FX Chain

On the GT-3 the effect order is set per patch. The bar shows the patch's own order, and the pedals stand in it too. Drag an effect to its new place, or focus it and move it with Alt + ← / →. Clicking an effect opens its detail panel.

The GT-3 plays a new order only after the patch is stored and loaded again. After a change the editor says so: press WRITE on the unit, then I pressed WRITE – load it again and the editor reloads the patch (or use the editor's Write, which reloads by itself).

At the end of the row is the Master module: the patch's output level and BPM (the tempo the note-value timings follow).

  • On / off: click the pedal's footswitch. A pedal that is on lights its CHECK LED and a red bar below it.
  • Type: on SFX, OD/DS, PRE, MOD and RV use the green ◀ ▶ window (click the name to pick from a list); on CS, WAH and DD the switch. Changing the type swaps the pedal's knobs.
  • Detail panel: a pedal only carries its main knobs. Click its name plate and a panel opens at the bottom with every parameter of that type, in groups. Esc or ✕ closes it.

Knobs: drag up or down with the mouse or a finger, use the mouse wheel (one step per notch), or focus one and use the keyboard: ↑ / ↓ one step, PgUp / PgDn a bigger step, Home / End minimum / maximum. On rate knobs the values above 100 are note values: 1/8 eighth, 1/8T triplet, 1/8. dotted.

6EXP / CTL / Assign page

These are part of the patch too: each patch can make the pedals do something different. On the left are the 10 controllers: the EXP pedal, the CTL pedal and Assign 1–8, each with whether it is on, what it controls and what moves it. For the selected one:

  • The switch next to its name turns it on and off.
  • Target: the 207 possible targets (any parameter of any effect, the master, manual mode, the tuner), grouped by effect. Min and Max are shown in the target's own units – milliseconds for Delay Time, for example. Picking a new target sets Min to its minimum and Max to its maximum. With Min above Max the control should work the other way round (not yet checked on the unit).
  • Source (assigns only): what moves it – the EXP pedal, the CTL pedal, the external SUB EXP and SUB CTL 1 / 2, the Internal Pedal, the Wave Pedal, or an incoming MIDI CC. Mode: Normal (follows the pedal) or Toggle (each press switches). The active range is the part of the source's travel the control acts in.
  • Response: the curve shows what target value each source position 0–127 gives.
  • Internal pedal: a virtual pedal that, when triggered (e.g. by a patch change or the CTL pedal), "presses itself" over the given time along the chosen curve. Wave pedal: moves the target continuously with the chosen waveform and rate. These cards are dimmed when they are not the source.

7Library page

All 340 patches in a table: name, PreAmp and OD/DS type, the SFX and MOD types when on, the effects that are on as coloured dots (in chain order), and the state:

  • Not read – not read from the GT-3 yet;
  • Editor only – changed in the editor, the GT-3 still has the old one;
  • Editing – the patch you are editing, with unsaved changes.

Filter at the top (User / Preset / All) or search by name. Click a patch number to open it on the Effects page. With patches ticked:

8System page

The GT-3's own settings, grouped as in the Qt program: Output (what amp / headphones the output feeds), Global EQ / NS / Reverb (a correction for every patch), Tuner, Controls (display contrast, dial function, the SUB CTL footswitches), Patch change, MIDI (receive / transmit channel, Omni, program change, the pedals' CC output) and Manual mode (what the footswitches switch in manual mode).

  • These are not patch settings: according to the Qt program the GT-3 stores every change at once, so there is no Write here (not checked on the unit yet).
  • Read from GT-3 (or System settings too in the Read (BULK) dialog) reads the GT-3's settings – in BULK LOAD mode. Until then, and offline, the defaults show.
  • Send all to GT-3 sends every setting shown (to restore a saved file, for example). Load file… / Save file…: all system settings in one file.

9What reaches the GT-3, and when?

  • Patch change: a Program Change at once; the GT-3 switches. The other way too: the editor goes to the patch picked on the unit.
  • Turning, switching, type changes, renaming: the change goes straight into the GT-3's temporary patch, so you hear it immediately (in normal mode). The GT-3's display doesn't show it: the old value may stay there and no "edited" mark appears – trust your ears.
  • Chain order: sent, but the GT-3 plays it only after the patch is stored and loaded again (section 5).
  • None of this is saved yet – changing patch loses it. To store: the unit's WRITE button (into the current patch, no BULK) or the editor's Write (into any user patch, through BULK LOAD).
  • Write / Write to GT-3: sent in BULK LOAD; the GT-3 stores it on EXIT, after its check.
  • System page: every change goes to the GT-3 at once, for good.
  • Loading files, Copy to…, Init: in the editor only – Write takes them to the GT-3.

10Saving and loading

Files go wherever the browser downloads to (usually Downloads), and you load them from wherever you like. The format is the Qt FloorBoard's .syx, with the patch description and creator, so files move freely between the two programs.

  • Save file… (header): This patch, as edited – the sound being edited, unsaved changes included; or All user patches – the 140 user patches in one file (the init patch for any not read yet).
  • Load file… (header, or drop the file on the window): a file with one patch goes into the editor (Write stores it); a file with many goes into the user slots (they become Editor only; Write to GT-3 on the Library page takes them over). A system settings file goes to the System page.
  • Backup: Read (BULK) → All 140 user patches (and System settings too), then Save file… → All user patches; and Save file… on the System page. After loading a saved file the patches are known – no need to read them again before editing.

11Troubleshooting

SymptomFix
"This browser has no Web MIDI"The browser has no Web MIDI (e.g. Safari, iPhone). Use Chrome or Edge.
"MIDI access denied"MIDI permission was blocked. Allow it in the site settings (the icon left of the address bar) and reload. If you opened the file directly and no prompt appears, start it from a local server (section 2).
"No MIDI ports found"The interface isn't plugged in or wasn't recognised. Plug it in and open the connection dialog again.
"could not open any MIDI input"Another program (the Qt FloorBoard, a DAW) holds the port. Close it and try again.
Reading fails ("expected 23 patch messages from the GT-3, got 0")The GT-3 answers only in BULK LOAD mode ("waiting"). Check the Device ID and the plugs (crossed over, all the way in, section 1). If it worked before and suddenly nothing comes: unplug and replug the interface's USB.
"expected 23 patch messages from the GT-3, got …" (more than 0)Only part of the patch arrived. Try again; if it keeps happening, the interface drops data on long SysEx messages.
Edits are not heardThe GT-3 is still in BULK LOAD: press EXIT. A chain order change plays only after storing and reloading.
Patch changes don't work, reading doesThe patch change channel differs from the GT-3's receive channel. Set it in the connection dialog to the Rx channel on the System page.
"Read (BULK)" / "Read from GT-3" is greyConnect first (section 3).
A change was lost after changing patchStore before changing patch: the unit's WRITE button or the editor's Write.
